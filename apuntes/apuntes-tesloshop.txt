🔷 react-router

En React, React Router es una biblioteca externa de terceros y por lo tanto, se instala como una dependencia en tu proyecto.
¿Para qué sirve?
React Router te permite simular la navegación de un sitio web tradicional de múltiples páginas dentro de una aplicación de React, sin recargar la página del navegador.
Con él puedes:
- Mostrar diferentes componentes según la URL actual (por ejemplo, / muestra el inicio y /contacto muestra el formulario de contacto).
- Manejar parámetros dinámicos en las URLs (como /productos/123).
- Crear rutas protegidas que requieren autenticación.

🔷 useRef
Es un Hook de react que te permite crear una referencia mutable que persiste durante todo el ciclo de vida del componente.
Este hook devuelve un objeto con una única propiedad llamada current (ej. miRef.current), la cual puedes leer y modificar libremente.
Para conectar el useRef con el elemento html tipo <Input, agregar al <Input la propiedad ref={nom_var_del_useRef}
A diferencia del estado (useState), actualizar un useRef no provoca un re-renderizado del componente.
-----

🔷 URLSearhParams
En JavaScript en general, URLSearchParams es una interfaz nativa del navegador que sirve para leer, crear y manipular los parámetros de consulta (query parameters) de una URL, es decir, todo lo que viene después del signo de interrogación (?) en una dirección web.
No es una característica exclusiva de React, pero se utiliza muchísimo en aplicaciones de React (junto con librerías como React Router o el hook nativo window.location) para gestionar el estado de la URL.
Cuando creas una instancia de URLSearchParams, esta retorna un objeto iterable (específicamente, un objeto de tipo URLSearchParams que actúa como un mapa o diccionario) que contiene todos los pares de clave-valor extraídos de la cadena de consulta de la URL.
A diferencia de un objeto de JavaScript tradicional ({}), este objeto no es un objeto plano, sino una estructura especial que viene con sus propios métodos integrados para consultar y modificar los datos.
🚨 A diferencia de useSearchParam, NO es reactivo por sí solo. Si la URL cambia, no re-renderiza tu componente automáticamente a menos que lo programes manualmente.

🔷 <Link ...> ... </ Link>
En React, específicamente cuando se usa la librería de enrutamiento React Router, el componente <Link> es el elemento estándar utilizado para navegar entre diferentes páginas o vistas de una aplicación de una sola página (SPA, por sus siglas en inglés).
A diferencia de la etiqueta HTML tradicional (<a>), <Link> permite cambiar de ruta sin necesidad de recargar la página completa.

<NavLink>: Es una versión especial de <Link> que sabe si la ruta actual está activa o no. Es sumamente útil para menús de navegación, ya que te permite añadir automáticamente una clase CSS (como active) al enlace en el que se encuentra el usuario actualmente.

----

🔷 useParams - (Parámetros de ruta)
Es un Hook de React Router que sirve para acceder a los parámetros dinámicos (segmentos de ruta) de la URL actual, dentro de una aplicación de React.
Cuando defines rutas dinámicas (por ejemplo, para mostrar el perfil de un usuario o los detalles de un producto), useParams te permite extraer fácilmente ese valor de la ruta para usarlo en tu componente (hacer una petición a una API, mostrar un título, etc.).

El hook useParams retorna un objeto JavaScript que contiene los pares clave-valor de los parámetros dinámicos de la URL actual.
Las claves corresponden a los nombres que definiste en la ruta precedidos por dos puntos :. Ejemplo: gender/:gender, clave = gender
Los valores son siempre cadenas de texto (strings) con lo que hayamos escrito realmente en la URL, valor = 'woman'

1. ¿Cómo se define la ruta?
En la configuración de tus rutas, marcas una sección de la URL como dinámica agregando dos puntos (:) antes del nombre del parámetro: /product/:idSlug
2. ¿Cómo se consume con useParams?
Dentro del componente que renderiza esa ruta, llamas a useParams(). Este devolverá un objeto con los pares clave-valor de los parámetros de la URL

🔷 cn

En el ecosistema de React (especialmente cuando se trabaja con Tailwind CSS y librerías populares como shadcn/ui), cn es una función utilitaria muy común que sirve para combinar, fusionar y gestionar clases de CSS de forma inteligente y condicional.
Su nombre viene de una abreviatura común para Class Name (nombre de clase).
La función cn no es una función nativa de React ni de JavaScript, sino que es la combinación de dos librerías externas muy potentes:
- clsx: Permite añadir clases de forma condicional (usando objetos, arrays o booleanos) sin complicarte con strings kilométricos. 
- tailwind-merge (twMerge): Resuelve los conflictos específicos de Tailwind CSS. Por ejemplo, si combinas px-2 y px-4, sabe que debe eliminar el primero y quedarse con el último.
Requiere importación con: import { cn } from "@/lib/utils";
¿Qué hace exactamente?
- Maneja condicionales limpiamente: Te permite activar o desactivar clases según el estado de tus variables o props.
- Elimina conflictos de Tailwind: Si un componente reutilizable ya trae un estilo por defecto (ej. bg-blue-500) y desde fuera le pasas otro (bg-red-500), cn se encarga de sobrescribirlo correctamente sin que Tailwind entre en conflicto o aplique estilos duplicados.
- Acepta múltiples formatos: Puedes pasarle strings, objetos condicionales o arrays indistintamente.

🔷 useLocation

El hook useLocation es una función incorporada en React Router (específicamente a partir de la versión 6) que sirve para obtener información sobre la URL actual en la que se encuentra el usuario dentro de una aplicación de una sola página (SPA).
Cada vez que cambia la ruta de la aplicación, este hook devuelve un objeto location actualizado que representa la ruta actual.
Propiedades del obj. location:
- pathname: (String) La ruta de la URL actual (por ejemplo, /productos o /contacto).
- search: (String) Los parámetros de consulta (query string) que van después del signo de interrogación (por ejemplo, ?id=5&sort=asc).
- hash: (String) El fragmento de la URL que empieza con # (por ejemplo, #seccion-2).
- state: (Any) Datos adicionales que se hayan pasado de forma oculta al navegar a través de la función navigate o del componente <Link>.
- key: (String) Un identificador único para esta ubicación específica.

🔷 Postgres

PostgreSQL (comúnmente llamado Postgres) es uno de los sistemas de gestión de bases de datos relacionales (RDBMS) más potentes, populares y avanzados del mundo.
En una arquitectura web tradicional (una aplicación construida con Node.js, Python/Django, PHP/Laravel, etc):
- El usuario interactúa con el Frontend (React, Vue, HTML).
- El Frontend hace peticiones al Backend (el servidor).
- El Backend procesa la lógica y se comunica con PostgreSQL para guardar o buscar los datos necesarios.
- Postgres devuelve los datos al Backend, y este los muestra al usuario.

-----

🔷 Docker

Docker es una herramienta de código abierto que se utiliza para crear, desplegar y ejecutar aplicaciones utilizando contenedores.
Docker permite empaquetar una aplicación junto con todo lo que necesita para funcionar (código, librerías, sistema operativo base, dependencias y archivos de configuración) en un único paquete estandarizado llamado contenedor.

Conceptos clave en Docker:

- Dockerfile: Es un archivo de texto plano que contiene las instrucciones paso a paso sobre cómo construir tu aplicación y qué dependencias instalar. Es la "receta".
- Imagen (Image): Es el resultado de leer el Dockerfile. Es una plantilla estática de solo lectura que contiene la aplicación y su entorno listo para ser ejecutado.
- Contenedor (Container): Es una instancia en ejecución de una imagen. Puedes pensar en la imagen como un plano de una casa y en el contenedor como la casa ya construida en la que puedes entrar y vivir.

Ejemplo práctico de uso:
Imagina que estás desarrollando una aplicación web en Node.js con una base de datos PostgreSQL:
- En lugar de instalar Node.js y PostgreSQL manualmente en tu ordenador (lo que puede ensuciar tu sistema), creas un archivo Dockerfile para tu app y descargas la imagen oficial de PostgreSQL.
- Con un solo comando (docker compose up), Docker levanta ambos servicios conectados entre sí en segundos.
- Cuando terminas de trabajar, puedes apagar y borrar los contenedores sin dejar rastro de instalaciones innecesarias en tu equipo.

🔷 TANSTACK QUERY

TanStack Query (anteriormente conocido como React Query) es una de las bibliotecas más populares para la gestión de estado asíncrono en desarrollo web.
En términos sencillos, es una navaja suiza para obtener, almacenar en caché, sincronizar y actualizar datos del servidor en tus aplicaciones frontend.

¿Para qué sirve?
Su objetivo principal es simplificar la comunicación entre tu interfaz de usuario y tus APIs (REST, GraphQL, etc.), resolviendo problemas complejos que antes requerían mucho código manual. Entre sus funciones clave destacan:
- Caché inteligente: Guarda las respuestas del servidor en memoria. Si el usuario navega a otra sección y regresa, los datos se muestran de inmediato sin hacer una nueva petición innecesaria.
- Sincronización en segundo plano: Actualiza automáticamente los datos de la pantalla cuando el usuario vuelve a enfocar la ventana del navegador o recupera la conexión a internet.
- Gestión de estados automatizada: Proporciona de forma nativa variables de estado como isLoading, isError, isFetching y data, evitando que tengas que crearlas manualmente con useState.
- Mutaciones sencillas: Facilita el envío de datos al servidor (crear, actualizar o borrar) y se encarga de revalidar o actualizar la caché automáticamente tras la operación.
- Paginación y Infinite Scroll: Incluye herramientas optimizadas para cargar datos por bloques o de manera infinita a medida que el usuario hace scroll.

¿Por qué deberías usarlo?
Tradicionalmente, para obtener datos se combinaban los hooks useEffect y useState, lo que derivaba en código repetitivo (boilerplate), posibles fugas de memoria y errores difíciles de depurar en los estados de carga.
TanStack Query te permite separar el estado del servidor del estado global del cliente (como Redux o Zustand). Esto hace que tu código sea mucho más limpio, rápido y fácil de mantener.

-----

🔷 Axios

Axios es una biblioteca de JavaScript extremadamente popular que funciona como un cliente HTTP. Su única y principal misión es realizar peticiones a un servidor (como peticiones GET, POST, PUT, DELETE) de forma sencilla, tanto desde el navegador como desde Node.js.

Es, básicamente, una alternativa más avanzada y cómoda al fetch nativo del navegador.

¿Para qué sirve Axios?

- Hacer peticiones HTTP: Envía y recibe datos de una API de manera limpia usando Promesas (Promises).
- Transformación automática: Convierte automáticamente los datos de respuesta a formato JSON (y viceversa al enviar).
- Interceptores: Permite interceptar peticiones o respuestas antes de que sean manejadas por tu código. Es ideal para añadir tokens de autenticación automáticamente o manejar errores globales (como un error 401 de sesión caducada).
- Manejo de errores mejorado: A diferencia de fetch (que no considera un error HTTP como un fallo de red), Axios rechaza la promesa automáticamente si recibe códigos de error como 404 o 500.
- Cancelación de peticiones: Permite cancelar peticiones en curso si el usuario abandona una página o componente.

La gran confusión: ¿Axios vs. TanStack Query?

Muchos desarrolladores novatos se preguntan cuál elegir, pero la realidad es que no compiten entre sí; se complementan a la perfección.
- Axios es el mensajero: Se encarga únicamente del transporte. Va a la API, trae los datos y te los entrega. No sabe nada de caché, ni de si el usuario cambió de pestaña, ni de reintentar la petición si falló el internet.
- TanStack Query es el cerebro: Se encarga de la estrategia. Decide cuándo hay que ir a buscar los datos, dónde guardarlos en caché para no saturar el servidor, cuándo refrescarlos y cómo manejar los estados de carga.

¿Cómo trabajan juntos?

En un proyecto real, utilizas Axios dentro de TanStack Query. TanStack Query le dice "necesito estos datos" y utiliza a Axios para ir a buscarlos.

JavaScript
// Ejemplo usando ambos juntos
const { data, isLoading, error } = useQuery({
  queryKey: ['user'],
  queryFn: async () => {
    // Aquí usamos Axios para hacer la petición HTTP real
    const response = await axios.get('https://api.example.com/user');
    return response.data; // TanStack Query guarda esto en caché automáticamente
  }
});

- Axios resuelve el cómo haces la petición.
- TanStack Query resuelve el qué haces con esos datos en tu interfaz.
